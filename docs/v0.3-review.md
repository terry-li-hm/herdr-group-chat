# v0.3 review protocol

The v0.3 direction is a focused review mode, not a general workflow engine.
Ordinary room messages retain the existing serial relay. `/review` adds one
coherent two-phase path for decisions that benefit from independent judgment.

## Contract

1. `/review [@reviewers] QUESTION` validates that every selected reviewer and
   the configured synthesizer is live before writing the question.
2. The relay freezes one prompt per reviewer containing the human question but
   no peer answer, then submits those prompts concurrently.
3. Each completion is appended immediately to the JSONL transcript with its
   stable review-round identifier. The transcript therefore preserves actual
   completion order; it never rewrites entries to manufacture roster order.
4. After every first pass reaches a terminal state, the configured synthesizer
   receives the original question and the usable answers in reviewer order. A
   missing answer is explicit rather than silently omitted.
5. The synthesis is appended last. If every first pass fails, blocks, times out,
   or is cancelled, synthesis is skipped.

Targeted mentions continue to select recipients. The default reviewer set is
the whole configured roster, capped by `--max-turns`. The synthesizer defaults
to Pi and can be selected with `--synthesizer` or
`HERDR_GROUP_CHAT_SYNTHESIZER`.

## Runtime behavior

The TUI runs a review in a background controller and reports per-participant
states: `queued`, `working`, `blocked`, `done`, `failed`, `timed_out`,
`cancelled`, `synthesizing`, or `skipped`. Navigation, transcript paging, retry,
and cancellation remain available while work is in flight; ordinary new
messages wait until the active review ends.

`/cancel` stops only the room's local orchestration and never sends Ctrl-C or
other terminal keys. Herdr 0.8 has no atomic sequence-conditional interrupt, so
a participant may continue working after local cancellation and its eventual
reply is not collected by the cancelled round. Timeouts, prompt failures, and
status failures likewise never interrupt a participant. `/retry AGENT`
generates a new reply marker, reruns that independent prompt, and synthesizes
again after success. `/retry
synthesis` reruns only phase two. Per-agent timeout overrides use
`--agent-timeout NAME=MILLISECONDS`.

## Deliberate boundaries

The current vertical slice keeps the fixed four-agent setup, stores retry state
only for the running room process, and does not add persistence orchestration,
network chat, or automatic model selection. Those are separate product choices,
not prerequisites for a useful independent-review room.
