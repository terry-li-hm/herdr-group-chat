# 0.12 redesign: agents by name, identity by process, layout as a re-runnable step

Date: 2026-09-03. Status: implemented on branch; awaiting release gate. A 1.0 label is reserved for after a month of weekly councils with no launcher defect.

## Why

On 3 September four defects shipped and were fixed in one day (0.11.1 to 0.11.3). Each was small; together they show one design fault. The launcher owns Herdr topology it cannot control: it records pane, tab and workspace ids that change on every `pane move` and vanish when Herdr auto-closes an emptied workspace, and it proves a model's identity by matching banner tokens on a screen that a short pane hides. The relay held up all day because it does neither: it routes by agent name through `agent prompt` and `agent get`, and keeps a transcript.

## What stays

- The relay `herdr-group-chat`: transcript journal, `/review`, `/anneal`, `/consensus`, resumable councils, `--once`, `/room`, `/inbox`, `/lanes`, the native-UI receipt entry, mouse and theme behaviour from 0.11.1.
- The seven actions and two pane entrypoints, so the smoke contract is unchanged.
- Settings (`layout`, `opus`), profiles and rosters, Sol as default synthesiser.
- `release-smoke` as the only release gate, plus the assays.

## What changes

### 1. Ownership by name

A participant is owned when `agent get <name>` returns an agent whose kind matches the participant and whose cwd matches the room's agent cwd. Nothing else. The launcher stops recording `participant_pane_ids`, `participant_tab_ids`, `participant_workspace_id` and `agents_workspace_id` as authority; it may cache them for display only. Reuse, reopen and adopt collapse into the same check, so `adopt-peers` becomes "re-run the owned check and report", and the workspace-label refusal disappears.

### 2. Identity by process

The only native proof is `pane process-info`: the foreground process's identity is exactly the participant's executable and its argv contains the participant's start arguments as one contiguous sequence. This is already implemented for reopen (`native_pane_process_proves`); promote it to the fresh-launch proof and delete the screen-token proofs (`*_PANE_PROOFS`, `pane_tokens`, `sequence_present`, `native_pane_proves`). A model rename in a vendor UI can no longer break a launch; only an argv change can, which is a change we make ourselves. Keep the Pi catalog preflight (`pi --list-models`) as the one pre-start check.

### 3. Placement as a pure, re-runnable step

`place(layout)` runs after every participant is owned and takes only live state from `agent get` and `pane layout`. `compact`: every owned peer that is not in a workspace labelled `agents · group-chat` is moved into one (created on demand), one tab per peer. `grid`: every owned peer is moved into the room tab as a right-hand stack with the probed `--ratio` arithmetic (target keeps the fraction; k-th of N peers uses 1/(N-k+2)). The step records the caller's workspace and tab first and restores them last, and it is idempotent, so a `/layout compact|grid` room command can re-run it at any time and a relaunch never depends on where the peers were left.

### 4. The room pane becomes optional

In `grid` the peer panes are the UI. The room pane stays as the input and transcript view, but every function it offers is also reachable without it: the cockpit drives rounds with `--once` and reads the journal. Reopen therefore never fails because a room pane is missing; it opens a new one.

### 5. Workspace lifecycle is Herdr's

The launcher never closes a workspace. Herdr closes an emptied workspace itself; the launcher tolerates `workspace_not_found` everywhere it lists or focuses, and treats it as "already gone".

## Deletions

`ownership_mismatch_reasons` workspace branch, `accepted_workspace_ids`, `close_empty_agents_workspace`, `adopted_workspace_acceptable`, the reopen re-verification of pane and tab ids, and every `*_PANE_PROOFS` constant with its tests. Expect roughly 600 lines of launcher and 150 assays removed, replaced by fewer than 200 lines and about 40 assays.

## Migration

Old launcher state files are read for `last_room_id`, `selected_profile` and `layout` only; every id field is ignored. No user-facing change to actions or settings; the room gains `/layout compact|grid`. Version 0.12.0.
